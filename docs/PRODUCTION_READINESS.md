# 서비스 출시 준비도 점검 (Production Readiness)

> 작성 기준: 2026-09. 코드 전수 점검 + 당시 테스트(SQLite·PostgreSQL) 기준 (현재 테스트 수는 CI 결과 참고).
> 법·규제 항목은 **변경될 수 있으므로 반드시 금융 전문 변호사·금융감독원 상담으로 확인**할 것.

---

## 0. 한 줄 요약

**엔진 구조·안전장치는 서비스급 뼈대를 갖췄지만, (1) 실제 데이터로 한 번도 검증되지 않았고, (2) 실제 계좌로 주문해 본 적이 없으며, (3) 남의 돈·남에게 신호를 다루는 순간 필요한 인허가·데이터 라이선스가 없다.**
세 가지 모두 코드가 아니라 **시간(실전 검증 기간)과 절차**가 필요한 일이다.

## 3. 부족한 점 (심각도 순)

### 3.1 [치명] 실제 데이터로 검증된 적이 없다
- 지금까지의 모든 수익률·Sharpe 는 **가상 데이터**다. 데모 데이터는 파이프라인을 보여주려고 모멘텀을 일부러 강하게 넣었다.
- 실제 국내 주식의 단기(5일) 방향 예측력은 보통 IC 0.01~0.03 수준으로 매우 약하고, 비용을 빼면 사라지기 쉽다.
- **해야 할 일:** 실제 5~10년 데이터(상장폐지 종목 포함)로 `quant-ai train` → 게이트 통과 여부 확인. 통과 못 하면 그게 정상적인 결과다.

### 3.2 [치명] LLM 은 과거로 백테스트할 수 없다
- LLM 은 학습 데이터에 이미 "그 뒤에 무슨 일이 있었는지"를 알고 있다. 2023년 뉴스를 주고 방향을 물으면 정답을 '기억'할 수 있다.
- 따라서 **LLM 애널리스트의 성적은 오직 앞으로(forward) 쌓이는 Shadow/Paper 성적만 믿을 수 있다.** 현재 구조(tracker)가 그렇게 설계되어 있다.
- **해야 할 일:** 최소 3~6개월 Shadow 로 AI 별 성적표를 쌓은 뒤에만 LLM 의 가중치를 신뢰. 그 전에는 Quant 모델 + Risk veto 중심으로 운용.

### 3.3 [치명] 인허가·데이터 라이선스 (4장)

### 3.4 [높음] 벤치마크 대비 성과
- 데모에서 전략 +15% vs 지수 +243% (가상 강세장). 종목당 10%·최대 50% 노출·롱온리 구조라 **강세장에서 지수를 크게 밑돈다.**
- 고객은 "지수보다 못한 AI" 에 돈을 내지 않는다. **해야 할 일:** 목표를 명확히(절대수익 vs 지수 초과), 지수 코어 + AI 위성 구조, 인버스/선물 헤지, 게이트에 정보비율(IR) 추가 검토.

### 3.5 [높음] 백테스트 편향
- 생존편향: 현재 유니버스는 '지금 살아있는 종목'. 상장폐지 종목이 빠지면 성과가 부풀려진다.
- 기업행동: 분할·병합·배당 조정(수정주가) 소스 확인 필요. 품질검사가 급변은 경고하지만 자동 조정은 안 한다.
- 재무 데이터: `asof_merge`(공시일 기준 결합) 도구만 있고 실제 재무 데이터 파이프라인은 없다.
- 슬리피지: 고정 5bp 가정. 소형주·호가 공백·VI 발동 시 훨씬 크다 → 실제 체결 로그로 재추정 필요.

### 3.6 [높음] 실제 주문 경로 미검증
- KIS 연동은 공식 예제 기준 엔드포인트·TR_ID 로 구현하고 가짜 서버로 테스트했지만 **실제 KIS 모의투자 계좌로 호출해 본 적은 없다.** 호가 응답 필드명(`askp1` 등)은 모의투자에서 확인 필요.
- 미구현: 실시간 웹소켓 시세(현재 REST 폴링), 해외주식 주문, 동시호가·VI·상하한가·거래정지 처리, 재시작 시 미체결 주문 복구(멱등성 키), 정정 주문.
- **해야 할 일:** `quant-ai kis-check` → `QUANT_BROKER=kis KIS_ENV=demo quant-ai run --mode live` 로 모의투자 계좌에서 최소 1개월.

### 3.7 [중간] 리스크 모델
- 종목별 한도만 있고 **상관관계**(반도체 3종목 동시 보유 = 사실상 1개 베팅), 섹터 한도, 포트폴리오 VaR/ES, 유동성(일 거래대금 대비 주문 비중) 한도가 없다.
- 합의 신호 자체의 확률 보정(consensus-level calibration)이 없다 — 복기의 '신뢰도 구간별 정확도'로 모니터링만 한다.

### 3.8 [중간] 서비스 아키텍처
- 단일 사용자·단일 계좌 구조. 서비스하려면: 사용자/조직/권한, 사용자별 포트폴리오·리스크 성향(적합성), 인증(비밀번호+2FA 또는 OAuth), 결제, 사용자별 격리.
- 확장: 웹을 ASGI(FastAPI)로, 작업을 큐(Celery/RQ/Arq)로 분리, LLM 호출 병렬화, 대시보드 캐시(Redis).
- 운영: 메트릭(Prometheus/Grafana), 로그 수집, DB 백업·PITR, 이중화, 비밀관리(KMS/Vault), 불변 감사 로그 저장소.

### 3.9 [중간] 보안 (외부 공개 전)
- 지금 인증은 단일 토큰. 다중 사용자 세션 인증, 요청 속도 제한, WAF, 의존성 취약점 스캔(CI), 외부 침투테스트 필요.
- 증권사 API 키는 사용자별로 암호화 저장해야 하고, 가능하면 서비스가 고객 키를 직접 보관하지 않는 구조가 낫다(규제와도 연결).

### 3.10 [낮음] 품질
- 프런트엔드 자동 테스트, E2E, 부하 테스트, 장애 주입(브로커·LLM 다운) 테스트, 재해복구 리허설.

## 4. 법·규제·라이선스 (서비스 전 필수 — 전문가 확인 필요)

> 아래는 일반적인 방향이며 법률 자문이 아니다. 2024년 이후에도 관련 규정이 계속 개정되고 있다.

### 4.1 무엇을 파느냐에 따라 필요한 자격이 다르다 (자본시장법)

| 서비스 형태 | 일반적으로 필요한 것 | 비고 |
|---|---|---|
| 본인 계좌 자동매매 (지금 단계) | 없음 | 증권사 API 약관 준수 |
| 불특정 다수에게 매매 신호·종목 추천 제공 (유료) | **유사투자자문업 신고** (금융위/금감원) | 2024년 개정으로 1:1 개별 자문·양방향 채널(단톡방 등) 영업 금지, 손실보전·수익보장 광고 금지 강화 |
| 고객별 맞춤 자문 | **투자자문업 등록** | 자기자본·전문인력 요건 |
| 고객 계좌를 대신 자동매매 | **투자일임업 등록** | 가장 엄격. 로보어드바이저로 하려면 **코스콤 로보어드바이저 테스트베드** 통과 필요 |
| 증권사·운용사에 엔진 공급 (B2B) | 계약 형태에 따라 다름 | 라이선스 부담을 파트너가 지는 구조 가능 |

- "AI 가 알아서 사고판다" 를 고객 돈으로 하려면 사실상 **투자일임업 + 로보어드바이저 테스트베드** 경로다. 개인이 바로 할 수 있는 영역이 아니다.
- 광고: 백테스트/가상 성과를 보여줄 때 가정·기간·비용·한계를 명시해야 하고, 수익 보장 표현은 금지.
- 기타: 개인정보보호법, (규모에 따라) ISMS-P, 전자금융 관련 규정, 고객 API 키 보관 방식.
- "상장(IPO)" 을 뜻한다면: 위 인허가 + 감사 가능한 재무·내부통제가 선행되어야 하며, 트랙레코드(실계좌 성과)가 핵심 증빙이다.

## 5. 권장 로드맵

| 단계 | 기간(최소) | 목표 | 통과 기준 |
|---|---|---|---|
| A. 실제 데이터 연구 | 1~2개월 | 상장폐지 포함 5~10년 데이터, 재무 point-in-time, 게이트 통과 모델 | PSR≥0.9, DSR≥0.5, IC t≥2, 비용 2배에서도 양수 |
| B. KIS 모의투자 Shadow/Live-demo | 3~6개월 | LLM 전진 성적 누적, 실제 체결·슬리피지 측정, 장애 대응 | AI 성적표 유의미(표본 수백 건), 실측 슬리피지 반영 후에도 양수 |
| C. 본인 계좌 소액 Live | 3개월+ | 실제 돈, `QUANT_LIVE_MAX_CAPITAL` 소액 | Shadow 대비 괴리 작음, 사고 0건 |
| D. 사업 형태 결정 · 법률 검토 | 병행 | 4장 표에서 경로 선택, 데이터 계약 | 변호사 의견서 |
| E. 서비스화 | 3~6개월 | 멀티테넌트·인증·결제·관측·보안 감사 | 침투테스트·부하테스트 통과 |

**가장 현실적인 첫 사업 형태:** 매매 실행 없이 "AI 시장 분석 리포트 + 멀티 AI 의견 비교 + 복기" 를 정보 서비스로 제공하면서(규제 범위 확인 필수),
실계좌 트랙레코드를 쌓는 것. 트랙레코드 없이 자동매매 서비스를 여는 것은 규제·신뢰 양쪽에서 어렵다.
