# 보안 현황 — 개인용 기준 (서비스 수준 아님)

화면 `#governance` 의 보안 점검표와 같은 내용입니다 (`governance.security`).

| 항목 | 상태 | 지금 | 서비스화 전 |
|---|---|---|---|
| 비밀 키 보관 | 🟡 | `.env` 에만 (저장소·DB·화면에 없음) | Secret Manager (클라우드 KMS) |
| 웹 접근 제어 | 🟢/🟡 | 원격 접속 시 `QUANT_WEB_TOKEN` 필수 · 로컬만 무토큰 | 사용자 로그인 · 세션 만료 · MFA |
| DNS 리바인딩 · CSRF | 🟢 | 허용 호스트 목록 · 쓰기는 JSON + 같은 출처(Origin)만 | 유지 |
| 보안 헤더 | 🟢 | CSP · X-Frame-Options DENY · nosniff · 정적 경로 탈출 차단 | 유지 + HSTS(HTTPS) |
| 감사 로그 | 🟢 | 긴급 정지·설정·계좌·알림 규칙·투자 논리·성향·모의 주문 기록 (추가만) | 별도 저장소 · 변경 불가 스토리지 |
| 예측 장부 위변조 방지 | 🟢 | 행 해시 · 해시 사슬 · 외부 공증(선택) | 유지 |
| 백업 · 복구 | 🟢 | SQLite 백업 7개 · 무결성 검사 · 재시작 따라잡기 | 관리형 DB · PITR · 복구 훈련 |
| MFA · RBAC | 🔴 | 없음 (1인용) | 필수 |
| DB 암호화 | 🔴 | SQLite 평문 | 디스크·컬럼 암호화 (계좌·거래내역) |
| 침투 테스트 · 취약점 관리 | 🔴 | 미실시 | 외부 점검 · 의존성 스캔 |
| AI 보안 (프롬프트 주입) | 🟡 | 뉴스·공시 텍스트는 '데이터'로만 넣고 그 안의 지시문을 따르지 않게 고정 · AI 는 주문 권한 없음 | 출력 검증 · 모델 공급자 데이터 처리 약관 |

**원칙**: 키는 절대 채팅·저장소·화면에 붙여 넣지 않는다. 원격으로 열 때는 토큰 + HTTPS 리버스 프록시.
