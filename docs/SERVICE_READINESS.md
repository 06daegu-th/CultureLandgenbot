# 서비스 준비도 점검 — "남에게 팔 수 있나?" (v0.23)

> 기준: **지금 이대로 다른 사람에게 돈 받고 제공한다면** 무엇이 막히는가.
> 직접 56개 메뉴 전체를 실데이터 서버로 열어 보고(PC 1440px · 모바일 390px · 쉬운/전체 화면),
> 검색·종목 화면·목표·세금·보고서를 써 본 결과입니다. 법률 내용은 **법률 자문이 아닙니다** (금융규제 변호사 검토 필요).

### 2-2. 처음 쓰는 사람이 막히는 곳

1. **설치가 개발자용**: 터미널 · `./run.sh` · `.env` 직접 편집. 일반인은 여기서 이탈.
   → 설치 파일(맥 .dmg / 윈도 .exe) 또는 웹 서비스(설치 없음)가 필요.
2. **키가 너무 많음**: `.env.example` 설정 65줄, 외부 키 10개 이상(Gemini·Groq·DART·FRED·ECOS·KIS…).
   → 서비스라면 사용자는 키를 몰라야 함 (운영자가 서버에서 한 번만). 개인용이라면 "필수 0개 · 권장 2개(DART·Gemini)"만 첫 화면에.
3. **메뉴 56개**: 쉬운 화면은 6개로 줄였지만, '전체'로 바꾸면 한꺼번에 56개가 나옴.
   → 서비스판은 "홈 · 종목 · 내 자산 · 목표 · 알림 · 설정" 6개로 고정하고 나머지는 관리자/연구 도구로 분리.
4. **용어**: 알파·MDD·VaR·섀도·챔피언·사다리 같은 말이 아직 전문가 화면에 많음.
   → 쉬운 화면에선 이미 대부분 우리말로 바꿨음. 전문가 화면은 용어에 마우스 올리면 한 줄 설명(툴팁) 필요.
5. **"그래서 오늘 뭘 하면 되나?"**: 홈의 '오늘 할 일'이 답이지만, 할 일이 없을 때 빈 화면처럼 보임.
   → "오늘은 할 일 없음 — 다음 확인: 금요일 CPI 발표" 같은 한 줄로.
6. **데이터가 차기 전 첫날**: 처음 실행 직후엔 일봉·뉴스가 없어 대부분 "-".
   → 첫 실행 마법사가 "데이터 불러오는 중 (약 5분)" 진행 막대를 보여 주고, 끝나면 홈으로.

### 2-3. 디자인 ("AI 같다 · 못생겼다")

| 문제 | 지금 | 제안 |
|---|---|---|
| 이모지 | 이번에 화면 전체 0개로 정리 | 앞으로 새 화면도 `lvDot()`·선 아이콘만 쓰도록 규칙화 (이미 `words.js` 에 정리기) |
| 카드가 너무 많고 크기가 다 같음 | 한 화면에 카드 10~20개 | 화면당 **주인공 카드 1개 + 보조 3개 이하**. 나머지는 '더 보기'로 |
| 글자 크기·굵기 단계가 많음 | 제목·부제·작은 글씨가 섞임 | 4단계(제목 20 / 소제목 15 / 본문 13 / 보조 12)로 고정 |
| 색이 많음 | 파랑·보라·청록 그라데이션 + 상태색 | 브랜드색 1개 + 상승(빨강)·하락(파랑) 국내 관례 + 회색 단계만 |
| 로고 없는 종목 | 이니셜 원 | 로고 API 연결 후 대부분 해결. 이니셜은 업종색으로 |
| 빈 칸 "-" 반복 | 위 2-1 참고 | 숨기기 or 이유 |
| 모바일 | 하단 탭 · 핵심만 보이게 정리됨 | 종목 화면 탭 이동을 스와이프로 · 숫자 폰트 크게 |

> 디자인을 근본적으로 바꾸려면 **디자이너 1명 + 디자인 시스템(색·글꼴·간격·컴포넌트 목록)** 을 먼저 정하고 화면을 다시 그리는 게 가장 빠릅니다.
> 지금 화면은 "기능을 다 보여 주는" 연구 도구 구조라, 서비스용으로는 홈·종목·내 자산 3개 화면을 처음부터 다시 그리는 것을 권장합니다.

## 4. 상용 서비스로 가려면 — 막히는 것 전부

### 4-1. 법·규제 (가장 먼저, 가장 비쌈)

| 하려는 것 | 해당할 수 있는 것 | 요건(요약) | 지금 상태 |
|---|---|---|---|
| 시세·뉴스·공시 보여 주기 | 정보 제공 | 데이터 이용계약 · 출처 표기 | 출처 표기는 됨 · 계약 없음 |
| 누구에게나 같은 "AI 확률·매수/매도 신호" | **유사투자자문업** (금융위 신고) | 신고 · 교육 이수 · 1:1 자문 금지 · 광고 규제 | 미신고 |
| 내 보유·성향에 맞춘 "이걸 사라" | **투자자문업** (등록) | 자본금 · 전문인력 · 내부통제 | 해당 기능 있음 → 서비스판에선 끄거나 "조건에 맞는 목록"으로 |
| 사용자 계좌로 자동 주문 | **투자일임업** (등록) | 자본금 · 전문인력 · 보안 · 감사 | 본인 계좌 전용 — 타인 제공 **금지** |
| 사용자 계좌·잔고 연결 | 마이데이터 · 개인신용정보 | 마이데이터 사업자 허가 또는 제휴 | 본인 KIS 키만 |
| 개인정보 (이메일·성향·보유) | 개인정보보호법 | 처리방침 · 동의 · 암호화 · 파기 · 유출 신고 | 단일 사용자라 없음 |
| 광고·마케팅 | 금융광고 규제 · 표시광고법 | 수익률 광고 금지(과거 수익 ≠ 미래) | 해당 없음 |

**현실적인 첫 단계**: "정보 제공 + 모의투자 + 본인 기록 도구"까지만 서비스하고, 매수·매도 신호는 **본인만 보는 연구 기능**으로 두는 것. 이 범위도 반드시 변호사 확인.

### 4-2. 데이터 라이선스 (두 번째로 막힘)

지금 쓰는 소스 중 **상용 불가 · 계약 필요**: KRX 시세(marcap 경유) · 네이버 금융 크롤링 · 야후 파이낸스 · KIS 시세 재배포 · 토스/알파스퀘어 로고.
→ 시세 벤더 계약(국내: KRX 정보데이터시스템 또는 코스콤 · 해외: Polygon/Tiingo 등)이 필수. 사용자 수·지연(실시간/15분 지연)에 따라 월 수십~수백만 원.
코드 쪽은 이미 1차/2차 소스 분리(`data/sources.py`)가 돼 있어 수집기만 교체하면 됩니다. 자세한 표: `DATA_LICENSES.md`.

### 4-3. 다중 사용자 구조 (기술적으로 가장 큰 공사)

| 항목 | 지금 | 서비스판에 필요한 것 |
|---|---|---|
| 계정 | 비밀번호 1개 + TOTP (한 사람) | 회원가입 · 이메일 인증 · 비밀번호 재설정 · 소셜 로그인 · 탈퇴 |
| 데이터 분리 | 모든 표가 한 사람 것 | 모든 표에 `user_id` · 행 단위 권한 · 사용자별 장부/관심/목표/알림 |
| 공용 vs 개인 | 섞여 있음 | 시세·뉴스·공시·AI 종목 분석은 **공용 1번 계산** · 장부·목표·알림은 개인 |
| DB | SQLite 기본 (Postgres 가능) | Postgres + 백업·복제 · 마이그레이션 자동화 |
| 프로세스 | 하나가 웹+수집+AI+매매 다 함 | 웹 / 수집 / AI 워커 / 알림 분리 + 작업 큐 (`SAAS_ARCHITECTURE.md`) |
| 키 | 사용자가 `.env` 에 직접 | 운영자 비밀 관리(Secret Manager) · 사용자는 키를 몰라도 됨 |
| AI 비용 | 무료 한도 | 종목별 분석 결과 공유(캐시)로 비용 ↓ · 사용자별 질문 한도 |

### 4-4. 보안

- 이미 있음: 비밀번호 해시 · TOTP · 로그인 잠금 · 감사 로그 · 키 값 화면 비표시 · 보고서 자동 가림.
- 서비스판에 추가: HTTPS 강제(지금은 로컬 HTTP) · CSRF 토큰 · 속도 제한 · 세션 만료/기기 관리 · 비밀값 암호화 저장 · 의존성 취약점 점검 자동화 · 침투 테스트 · 개인정보 영향평가 · 증권사 키를 서버에 보관한다면 HSM/KMS 수준 보관.

### 4-6. 사업

- **누구를 위한가?** 지금 기능은 "AI 매매 연구자"용과 "적립식 초보 투자자"용이 섞여 있음. 하나를 고르는 게 먼저.
  - 초보 적립식: 목표 계획 · ISA/연금 세금 비교 · ETF 월 적립 · 쉬운 알림 → **규제 부담 낮고 수요 큼** (추천)
  - 액티브 트레이더: AI 신호 · 종목 분석 → 규제 부담 큼 · 성과 증명 전엔 팔기 어려움
- **차별점 후보**: "AI 가 틀린 것까지 전부 공개하는 성적표" · "ETF 그냥 샀을 때와 매달 비교" · "세금 계좌 비교" — 경쟁 앱이 잘 안 보여 주는 것들.
- **요금**: 데이터·AI 원가가 사용자 수에 비례하므로 무료 등급은 지연 시세 + 질문 한도, 유료는 실시간·알림·세금 리포트.
- **신뢰**: 성과를 광고하지 않는다 (규제 + 신뢰). "검증 중" 상태를 그대로 보여 주는 지금 방식이 장기적으로 맞음.
